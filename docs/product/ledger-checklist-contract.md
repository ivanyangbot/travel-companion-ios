# 账本 Agent 的清单契约

账本包含支出、卡包、备忘。`agent=ledger` 只标识工作区，不构成新增支出的意图。
请求的 `message` 必须保留用户原文，不再追加 `[Ledger output rules]`；支出规则统一由后端维护。

后端对明确的非财务清单请求应用只读任务边界，兼容旧客户端附带的规则后缀。
也支持调用方明确发送 `intent=checklist`。有费用要求的混合请求继续交由模型分别输出清单和支出。
模糊请求由模型结合对话判断，不将所有“清单”关键词都强制视为行李清单。

模型通过 `result.checklist` 输出独立结果：

```json
{"title":"印尼行前准备清单","items":[{"text":"护照","note":"检查有效期并随身携带"}]}
```

每项只有 `text` 和可选 `note`，最多 50 项，不承载金额、日期或已付款状态。
本机备忘勾选不等于付款，已付款也不等于已打包；已有物品仍可出现在携带清单。

后端验证结果后发送完整 `assistant_delta` 文字清单、扩展 `checklist` 事件及空 `change_set`。
现有客户端忽略未知事件，照常显示文字清单；混合任务单独发送真正的支出候选。
清单不进入 `candidate_upsert` 或 `/v2/agent/commits`，不触发金额补全。
这版提供对话内清单展示，尚未实现交互勾选或写入本机 `LocalMemoList`，不得声称已保存备忘。

清单模式不注册汇率工具，必要时仍可搜索外部事实。错误支出输出先修复，最多三次；持续失败则明确提示生成失败，绝不展示或保存误生成的费用卡。
回归覆盖：截图六项、缺金额但无需记账、模型追问金额、持续错误输出、混合请求、旧客户端消息后缀与未知 SSE 事件兼容。
